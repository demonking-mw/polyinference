Why this architecture

Two pipes, eight nodes

Read each pipe from top to bottom. The left pipe contains the cloud senior, sprint queue, coordinator, and project acceptance. The right pipe contains the local agent, tools and observations, task verification, and committed result packet. Cross-pipe arrows explain how the senior assigns work and how the worker returns evidence. There are no group boxes.

The first model call goes to the cloud. Initial interpretation, review, planning, hard-task execution, and completion use different prompts inside the same cloud-model node. The local-model node likewise reuses one bounded loop across task-specific prompts. The host validates plans and dispatches work without paying for a supervisor at each step.

A sprint ends when its queue is exhausted or stalled, a worker cannot recover within its allowance, assumptions change, or integration regresses. The weekly meeting analogy expresses cadence; it does not impose a timer. A long project can contain many such sprints.

The local loop is a real coding agent

Each assignment gets a scoped prompt, tools, base revision, acceptance checks, and step/time/token limits. The local model proposes actions, the host authorizes and executes them, observations return, and the loop repeats. A candidate or exhausted allowance goes through independent checks and a verdict. Multiple logical juniors can use a single local endpoint sequentially.

Every closed task produces a Git checkpoint

A passed, failed, blocked, or budget-exhausted task closes with a scoped commit. A no-diff task uses an empty metadata commit. Failed work stays on its task branch. The host verifies the SHA and evidence before ingesting the report; only accepted work is promoted and unblocks dependencies. If Git or the process fails before a checkpoint exists, the attempt remains interrupted and is reconciled before closure.

{
  task_id, attempt_id,
  verdict: "passed | failed | blocked | budget_exhausted",
  observation,
  tests: [{ command, status, exit_code, revision, output_ref }],
  base_sha, commit_sha, evidence_refs, usage, blockers
}

Deterministic by default, agentic where useful

The cloud makes strategic decisions. Host code handles leases, counters, dependency readiness, ordinary routing, and known pass/fail checks. An optional, bounded cloud classifier can interpret an ambiguous exception. A deliberately assigned hard task selects the cloud endpoint inside the same bounded execution harness and produces the same evidence and commit packet.

Independent completion

Queue exhaustion triggers a cloud review. Completion requires a senior completion decision and project checks on the integrated tree. Passing task tests alone does not prove integration. Every model request and tool action respects the current global and task budgets; exhausted budget can stop the run without another paid call.

Editor tools

Move & connect

Drag any state. Edges recompute their boundary ports and route around node rectangles; they have no stored bend points. Drag the background to pan. Zoom with the wheel, or use the bottom controls. In Connect mode, click a source then a destination, or press Escape to cancel. Select a state and use arrow keys to nudge it (Shift for larger steps).

Edit & preserve

Click a state or arrow, then Edit. Add and remove states or transitions in the inspector. JSON export preserves the graph; Save HTML makes a standalone editable copy with your current design embedded. Browser autosave is a convenience: export a copy for reliable backup. Imports accept this v2 schema and the old v1/v0 JSON; obsolete fixed edge waypoints are discarded.
