## Implemented scope

- Local development tasks require one production implementation file plus scoped
  tests/documentation. local_contract pins input/output shapes, functions/objects,
  state ownership, side effects and errors. A behavior, focused check and observable
  acceptance criteria are mandatory. Prompts request small behaviors; planning,
  effective allocation and task construction enforce the structural boundary.
- Irreducibly coupled specialist work declares cloud_only_reason. It survives
  task-count allocation and still uses original finite campaign resources/grants.
  Existing automatic cloud recovery remains protected and bounded.
- OSTuning's nested collections/environment are immutable. HTTP environment trust
  controls actual proxy routing. Snapshot/export/checkpoint readers inherit the
  original run's SQLite timeout, with a canonical bootstrap fallback only when
  an independent historical database must first reveal its saved policy.
- One system.local_token_limits pair drives local API output requests, input
  packing/enforcement, context sum, token-pool admission and prompt/capacity views.
  Legacy duplicate fields become compatibility projections. Saved/restarted values
  resolve consistently. Strata startup JSON derives --max-context from the sum;
  configure-local changes no running process and retains the original launch file.
  Separate/inline context flags are supported; ambiguous or invalid arguments reject
  without rewriting the launch file.
- Cloud agents have no OS per-call input/output token cap or endpoint token-pool
  ceiling. Codex receives no token allowance instruction, even on the local worker binding. Completed native usage
  is labeled as cumulative thread usage, separate from final-response completeness.
  Campaign accounting/deadlines, byte limits and authority remain applicable.
- Completed local overages retain their complete output as CompletedBudgetExceeded,
  with usage scope and violation facts, rather than IncompleteGeneration. There is
  no automatic smaller-response replay. Actual truncation never becomes an action.
- Diagnosis and senior private-exception review receive matching passing and failing
  checks. Selection binds process, repository, tree, environment and configured
  invocation; latest conflicting verdicts remain visible. A bounded diagnostic
  capability pages only check outputs in that frozen catalog. Passing checks do
  not mint reconciliation, publication or objective-acceptance authority.

## Pins and compatibility

Current pins: simple-os/6, agent-9-local-contracts, state 2.8. Use fresh state;
historical source/configuration/resources are not migrated or replenished.
The application owns decomposition, Git, acceptance and provider startup preferences.
The OS owns generic authority/effects/admission/accounting. Actual provider scheduling,
tokenization and hidden native context remain outside OS control.

[Local token settings](../docs/guides/local-token-limits.md) explain migration,
Strata restart ordering and API/native differences. Raw cloud APIs which mandate an
output-token field require a capped local-lane stand-in or a provider-managed harness;
the OS does not invent an implicit cloud cap. Local convergence is still unqualified.
