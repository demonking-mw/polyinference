# Worker recovery and progress

Clean worker exceptions preserve a scoped development delta and abandoned-view snapshot. Eligible local
exceptions transfer to a specialist bound to `cloud`, including retry/defer/stop/omitted senior decisions.
The application records the raw model proposal and effective policy adjustments. This is coding takeover,
not merely cloud review or read-only diagnosis. Ordinary allocation cannot demote it. Cloud failures cannot
bounce back to local or reset their cloud count. Ineligible exceptions retain retry/defer/stop semantics and
exact blocker reasons. Explicit `resume_from=exception_ref` selects the retained delta; without it the
replacement starts fresh. Replacement grants cannot exceed the original grant; accounts, reserves and
absolute deadlines carry forward. Deferring an exception allows independent work but leaves a completion
obligation. Source conflicts use a fresh current base for automatic cloud repair while preserving the old
delta. Pending consumers are replaced transitively; started contracts stay pinned. No role change bypasses
unknown effects, explicit cancellation, publication, exhausted resources or unavailable cloud binding. See
worker recovery (`design-docs/implementation/WORKER_RECOVERY.md`).

New source, previously unread ranges and new check evidence count as progress.
Repeated reads and checks, renamed or empty searches, narration and rewritten
memory do not reset stagnation. Active or unknown execution suppresses semantic
escalation. Native jobs are sampled between settled jobs. The configured
thresholds do not establish model convergence. See
`design-docs/implementation/PROGRESS_MONITORING.md`.

Read `docs/modules/assignment-contracts.md` for local edit and test-only task
rules. A failed test-only observation reaches manager review without automatic
coding diagnosis. Test retries retain their read-only scope and original resources.

Clean retryable output exhaustion after OS repair receives bounded diagnosis
before linked recovery. Native diagnosis may use read-only calls on frozen
source and cataloged check output. Raw diagnosis uses previews. Matching
passing and failing receipts also reach senior review; they do not establish
acceptance. Resolved search and protocol errors leave the active worker hints
while their original evidence stays immutable.

Use fresh state when source, configuration or program pins change. See the runtime
boundary continuation guide (`design-docs/simplified-os/boundary/continuation.md`)
for the exact predecessor exception. Use `docs/guides/qualification.md` to separate
fixture results, live runs and completion evidence. The 26 October records
are under `docs/temporary/investigations/`.
