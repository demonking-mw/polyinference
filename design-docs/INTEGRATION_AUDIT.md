Reviewed the [simplified OS](simplified-os/README.md) and [LangGraph agent](langgraph-agent/README.md) as one system, using the [merged execution/memory graph](polyinference-design/polyinference-agent-design-merged.json), [merge notes](polyinference-design/merged-agent-design-notes.md), [concurrency protocol](polyinference-design/concurrent_coding_protocol.md), older OS proposal, five lecture derivations and agent handbooks as supporting evidence. The original lecture/planning PDFs are absent. Vendored source is supporting material, not an independently audited product or additional authority.

The main split is coherent: the agent owns sprint/task meaning, prompts, assessment and senior decisions; the OS owns admitted effects, isolation, ownership, persistence and accounting. Local token batching remains the serving engine's job. The issues below were gaps or inconsistencies in the combined contracts. They do not establish that an existing runtime has these bugs: neither runtime has been implemented here.

## Findings and corrections

| ID / importance | Gap and concrete consequence | Correction in the current designs |
| --- | --- | --- |
| A1 · high | Acceptance required current reviewed evidence without a complete exclusion/compare protocol. A worker could publish after the selected snapshot, or steering could arrive during checks, leaving `completed` attached to stale authority. | Close starts, settle workers, acquire verification, require reviewed = provisional and resolved contributing work, then check the full private revision. Compare heads, plan, steering, current owner and active-worker/effect predicates when recording completion. New input invalidates the attempt. ProjectRun rejects locally contradictory completed records. |
| A2 · high | Ordinary review could activate a new plan while old workers were still executing, while steering explicitly preserved their old instructions. The older research's stale-plan quarantine default also conflicted with that promise. | Use a conservative review barrier: close starts, drain started work, pin the senior input, reconcile dispositions, then activate the next plan. Exception review can inspect a parked blocker without falsely acknowledging steering. Do not hold verification while awaiting workers/senior. Stale proposals fail comparison; later input stays pending. |
| A3 · high | The wire `publication` payload requires a worker report, but senior revert also changes the shared head. Treating both identically would require a fake worker completion or bypass effect recovery. Multiple reverts cannot be one transaction across Git and metadata. | Senior head updates use journaled generic `capability_call` + immutable arguments + atomic record publication, with explicit resolution/evidence/receipt, under verification. Worker reports remain worker-only. Recover each disposition intent before continuing the batch or acknowledging the plan. |
| A4 · high | Abort retained an integrated tree but only specified reacquiring a fresh head. Diffing that tree against original B would attribute predecessor changes to the resuming worker; old checks could also survive a view switch. | Retire the aborted generation and final-phase evidence. The minimal resume path rebuilds from the preserved original private delta at fresh H, then repeats reconciliation/checks/assessment. Abandoned reconciliation repairs stay available for explicit reapplication. A recovered published receipt finishes the original attempt. |
| A5 · high | W bounded resident workers without an explicit relationship to completed-unresolved reports or senior capacity. Retaining every unresolved worker slot can prevent further dispatch; putting senior work behind the same pool can prevent the review that unlocks progress. | Count setup, active/waiting workers and needed cleanup against W. Release the slot after known completion/publication/cleanup, independently of senior disposition. Reserve bounded controller/recovery/senior host capacity. Retained reports and workspaces consume separately bounded storage. |
| A6 · high | The delta validator allowed add-over-existing, rename-over-existing and a rename source also modified elsewhere. Integration manifests were not linked back to their actual delta/owner/scope. Full visibility could be mistaken for full write authority. | Treat deltas as non-overlapping changes against B. Check both rename endpoints and known existing destinations; require the broker to prove absence in B for new destinations. Link integration to the same task/owner/base/delta and unchanged write grant. Reject Git control paths. Validate final H-to-P scope; rehash after tools/hooks before accepting evidence. |
| A7 · medium | The profile hard-coded the hybrid role map, while both designs asked for all-local/cloud comparison runs. The OS process diagram also used `advancing` where the wire enum uses `running`. | Pin a feasible static role map per run; preserve cloud-senior/local-worker as the reference default. Alternative experiments supply matching role policies/capability/data constraints without runtime migration. Use the existing `running` lifecycle name. |
| A8 · medium | One active effect per process conflicted with brokered callbacks during a native agent job. A native senior query also lacked an explicit mapping to AgentJob's workspace/protocol fields. | Limit top-level effects; journal real callbacks as subordinate operations with stable ancestry and inherited grants/budget while retaining the parent job reservation. A senior job names a read-only snapshot/query protocol. Unsupported agent-job execution fails negotiation; raw inference remains the bundled profile. |
| A9 · medium | Shape checks accepted unseen/applied steering, open barriers with pending input, named permits absent from retained ownership, and tool results preceding their calls. An acceptance scenario also promised no double charging beyond what arbitrary providers guarantee. | Add semantic counterexamples and validators for watermarks/barriers, retained permits and ordered context pairs. State that journal settlement is idempotent, ambiguous work is reconciled, and real provider executions remain billable. No exactly-once external billing guarantee. |

These corrections are implemented in both design READMEs and the relevant Python validators/check helpers. The merged HTML/JSON and historical research are retained as provenance. The audit refines missing execution details; it does not rename diagram components or rewrite the deliberately preserved memory graph.

## Verification and remaining work

The contract helpers validate the existing linked fixtures and source graph provenance, plus negative cases for the corrected static invariants. Positive checks retain ordered tool pairs, explicit add/delete/non-overwriting rename, uncertain publication with retained ownership and alternate static role maps. Validating alternate maps proves their shape only; actual role eligibility and hardware fit remain deployment checks.

Validation passed: 35 illustrative agent records, six workspace views and three private deltas; 76 invalid/unsupported combinations rejected (24 added in this audit). Both regenerated JSON schemas match their models; their wire shapes are unchanged. The merged graph checker passed all 159 visible routes, and all 101 local links in the five current/audit documents resolve. Commands: `python -B design-docs/langgraph-agent/validate_contracts.py`, `python -B design-docs/simplified-os/validate_contracts.py`, and `node design-docs/polyinference-design/check-merged-graph.cjs`.

The wire shape remains 2.0 and state shape 2.1; the program is now `proposal-4-audited-core`. Earlier program continuations must not silently resume with changed review/recovery semantics. Graph/prompt hashes in the fixtures remain illustrative; the merged source-design digest is checked against real file bytes.

Before implementing broader features, exercise these schedules in the actual adapter:

| Schedule | Required observation |
| --- | --- |
| W slots full; reports need review | Senior/control/recovery can run; finished unresolved reports no longer occupy W. |
| Review threshold reached while a worker waits for verification | Starts close; that worker can still enter and finish; review holds no gate needed by the drain. |
| Steering arrives during a senior query or acceptance checks | Input is retained, not acknowledged by the stale snapshot; no new coding start or stale completion. |
| Review publishes two reverts and crashes between them | Recovery returns the first receipt and performs only the remaining authorized intent; no duplicate inverse commit or premature plan activation. |
| Integration aborts after predecessor code was merged | Fresh H is captured; predecessor code is not replayed as the owner's private delta; final assessment is repeated. |
| A test/formatter/hook modifies assessed source | Content mismatch invalidates evidence; publish only after scope validation and renewed checks/assessment. |
| A native job requests a brokered shell action | Parent cloud occupancy remains; child operation acquires shell and inherits grant/budget; observational replay does not run it again. |
| A supposedly new file exists in B outside the partial copy | Broker rejects the add/rename destination; absence from the manifest is not proof of absence. |

No agent, OS scheduler, sandbox, Git integration protocol, native endpoint, inference batching or benchmark was executed. Hardware/model/backend selection, measurable memory/context capacity, concrete sandbox enforcement, configured criteria, budget prices/limits and supported LangGraph/saver versions remain implementation inputs. They are not resolved by documentation or schema validation.
