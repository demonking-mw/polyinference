Reading the changes

Blue S1–S7 badges identify changed states; arrow inspector comments explain ownership and phase transitions. Solid arrows carry work/results; dashed arrows carry exceptions or control barriers; dotted arrows show service/context dependencies. The Data & memory view retains the deferred Key frame. These are design contracts, not a running OS.

S1

Private copies, parallel development

Graph change. Each in-progress agent gets a copy at base B; workspace creation is explicit before the local loop. Private edits/reasoning overlap; non-shell edits do not use a global coding permit.

Why. Copies separate work; partial copies need enough build/test/dependency context to support valid reconciliation.

S2

Serialize reconciliation before assessment

Graph change. The candidate requests Verification critical section, captures latest head H, merges it, and runs at least one specially prompted development loop before the final assessment loops. Ownership remains held through repair, commit and publication.

Why. A clean merge can still introduce semantic changes. One development iteration is required but is not proof of correctness.

S3

Two mutexes with one order

Graph change. Shell mutex admits one command globally; Verification critical section admits one final-phase process. Inside verification, take/release shell individually. Outside shell owners release before requesting verification.

Why. This preserves your two independent critical sections and prevents shell→verification→shell deadlock while the coordinator keeps running.

S4

Publish the predecessor before release

Graph change. Commit/report publishes provisional_head=P and the unresolved report before verification release. The next entrant captures and merges that P; a commit existing only in a private copy is insufficient.

Why. The handoff must make the preceding agent's actual work visible and survive a crash without duplicate publication.

S5

Steering waits for running locals only

Graph change. New local starts stop; currently in-progress agents, including shell/verification waiters, finish their existing sequence. The planner then receives steering and unresolved reports.

Why. Pending unstarted tasks must not delay steering, and gates must still let the captured running set finish.

S6

Unresolved publication and senior undo

Graph change. All completed verdicts publish provisionally with hazards and remain unresolved. Senior keep/revert/retry/defer is separate; revert uses verification/shell rules and checks downstream effects.

Why. Publishing code is not approving it. Preserve an attributable commit parented on H so undo does not also reverse inherited changes.

S7

Recover both owners and publication state

Graph change. Resume manifests retain copy/base/head, phase, both owner refs, pending effects, commit and publication/report identities.

Why. A timeout, crash or saved frame does not prove protected work stopped; reconcile before unlocking or allowing resumed publication.

Shared publication is provisional

This graph adopts the proposed sequence: each completed process, including fail/uncertain, publishes its commit with hazards before releasing verification ownership. The next process merges that head. Every local report remains unresolved until senior review. A different policy retaining questionable work privately is a design choice in project_design.md, not silently assumed here.

The graph is the agent design, including OS-handled program services. No computer-kernel integration is involved. concurrent_coding_protocol.md contains the complete sequence, lock ordering, publication and recovery contracts. Editable exports preserve both graph views and these explanations.

Contract updated

Why this architecture

Parallel private development, serialized final phase

Each coding process owns a codebase copy. Every shell command takes the global shell mutex. A separate verification gate covers latest-head merge, at least one reconciliation development loop, final assessment, commit and provisional head/report publication. Hold it until publication; take shell individually inside it.

Ordering and review

Acquire verification before shell when both are needed; release outside shell ownership before requesting verification. All normal local completions remain unresolved, including successful ones. Senior review may keep/revert/retry/defer; revert follows the same gates and examines blast radius. Steering waits for currently running locals, not the pending queue.
